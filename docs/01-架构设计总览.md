## 1. 设计支柱：信息不透明 + 体力成本

作者提出的所有"硬核"环节，归根结底是同一种东西：

| 环节 | 信息不透明 | 体力成本 |
|---|---|---|
| 进货 | 不知道未来时尚趋势 | 挑选、规划数量 |
| 仓储 | 箱子外面看不出里面装什么 | 搬箱、摆放 |
| 物流 | 路线、路况 | 开车小游戏 |
| 整理 | 货架上的货从外部无提示 | 手动摆放、手动拿取 |
| 经营 | 客人的接受价、性格、策略全部隐藏 | 手动拿货、手动算账 |
| 员工 | 隐藏性格缺点、是否在摸鱼或贪腐 | （替玩家承担体力） |
| 批发赊账 | 对方会不会真的还钱 | 催账 |

**技能系统和员工系统的本质，是用经验值和工资把"信息"和"体力"买回来。**

核心循环：

```
亲手干活 ──→ 积累经验、现金、信誉
    ↑              │
    │              ▼
    │       买回信息（技能）、买回时间（员工）
    │              │
    │              ▼
    └──── 员工带来新的不透明（摸鱼、贪腐、拖账）
                   │
                   ▼
            更高级的技能去看穿（客人观察 / 员工观察）
```

**设计准则**：每新增一个功能，必须回答"它制造了什么不透明，又用什么代价换回透明？"。答不上来的功能砍掉。

> 这个支柱本身就是可玩性：它和《Papers, Please》《Shenzhen I/O》属于同一类乐趣，即"拟真的苦差事 + 玩家逐渐变得精明"。

## 2. 整体架构：两层世界

这是最重要的一条架构决定，所有模块都建立在它之上。

### 2.1 真相层（Truth）

游戏世界的客观事实，玩家永远不能直接读取：

- 每条围巾的真实属性与品质
- 每个箱子里实际装了什么
- 每位客人的真实心理价位、性格、策略、信用
- 每位员工的真实性格、缺点、当前满意度、是否在作恶
- 未来 N 天的真实时尚趋势向量
- 仓库的真实湿度 / 货物真实受潮程度

### 2.2 认知层（Knowledge）

玩家"以为"的世界，是真相层的**有损采样**。来源：

| 认知来源 | 对应真相 | 失真方式 |
|---|---|---|
| 箱子上手写的标签 | 箱内物品 | 可能写错、可能过期（货被挪走后标签没改） |
| 强化记忆技能 | 箱内 / 架上物品 | 只覆盖最近 N 次操作过的槽位，N 随等级增长；显示的是操作当时的快照 |
| 洞察时尚技能 | 未来趋势 | 低级带噪声、只给一个维度；高级精确、多维度 |
| 客人观察技能 | 客人心理价 / 性格 | 低级只给区间与模糊性格；高级给精确值 |
| 员工观察技能 | 员工缺点 / 满意度 | 低级只看到情绪；高级能看到动机 |
| 账本 | 实际库存与现金流 | 员工贪腐时账本与真相不符 |

**所有技能的实现，都是"调一个采样函数的噪声 / 范围 / 时限参数"**，不需要每个技能单独写逻辑。

### 2.3 玩家与员工共用动作接口

```
ActionAPI
├── move_box(from_slot, to_slot, actor)
├── place_item(item, slot, actor)
├── take_item(slot, actor)
├── sell(item, price, customer, actor)
├── purchase(order, supplier, actor)
├── write_label(box, text, actor)
└── ...
```

- 玩家通过输入调用这些接口；员工 AI 按自己的性格参数调用同样的接口。
- **摸鱼** = 动作间隔变长、动作成功率下降。
- **收回扣** = `purchase` 的实际单价被加价，差额进员工口袋。
- **偷货** = 一次没有记入账本的 `move_box` / `take_item`。
- **发现贪腐** = 账本与真相层对账出现差异 → 触发玩家可选的处置流程。

这样"委托给员工"几乎是零额外成本，而且贪腐的证据天然可追溯。

## 3. 时间模型

### 3.0 时间单位：旬

玩家的一次完整经营在游戏里称为**一旬**（而不是一天）。这样一年只需 36 次经营就能走完春夏秋冬，季节与经济周期都能被玩家真实体验到。

| 单位 | 换算 | 游戏内意义 |
|---|---|---|
| 旬 (`period`) | 1 次经营 | 实时营业 + 旬末结算 |
| 月 | 3 旬 | **贷款分期还款**、工资、租金 |
| 季 | 9 旬 | 季节更替 → 材质偏好基线变化 |
| 年 | 36 旬 | **经济完整周期**，宏观参数发生一次随机调整 |

- 代码里统一用 `period`（整数，从 1 开始累加）作为时间轴；`season = ((period-1) % 36) // 9`，`year = (period-1) // 36 + 1`。
- 所有"每天"的旧表述一律理解为"每旬"。

- **旬内**：实时推进，可暂停、可 1x/2x/3x 加速。店铺营业、开车、整理都在旬内。
- **旬间**：每旬结束进入"结算 + 规划"界面：本旬收支、库存变动、信誉变化、账期提醒、趋势回顾（只看过去，不看未来）。规划界面不走时间。
- **周期性事件**：每 3 旬结算租金、工资、贷款分期；每 9 旬换季；每 36 旬经济完整周期调整；供应商新品按旬刷新。

### 3.1 一旬的实际时长：同类游戏参考

| 游戏 | 一天实际时长 | 备注 |
|---|---|---|
| Stardew Valley | 约 14.3 分钟 | 游戏内 10 分钟 = 7.2 秒，6:00–2:00 |
| Travellers Rest（酒馆经营） | 21 分钟 | 6:00–3:00，有缩短的"短日" |
| Supermarket Simulator | 未公布，玩家普遍抱怨"太快、太赶"，要求加时间流速滑块 | 开店前时间不走 |
| Recettear / Moonlighter | 无固定实时长度 | 分阶段，只有"开店中"才走时间，准备阶段时间冻结 |

**结论与建议**：
- 目标 **12–18 分钟 / 旬**（纯开店营业时间），落在 Stardew 与 Travellers Rest 之间。
- 借用 Recettear / Moonlighter 的做法：**只有营业、开车、仓库作业时时间才走**；进货下单、看账本、规划摆放时时间冻结。这样硬核环节不会被时钟逼着赶。
- 提供**时间流速滑块**作为设置项（Supermarket Simulator 玩家最大的呼声），而非只有固定倍速。
- 具体数值在阶段 0 做出来后用实测调，不要现在定死。

### 3.2 视角与表现（2026-10-19 修正）

- **视角**：仰视 + 斜 45° 的开罗游戏（Kairosoft）式斜投影，不是俯视。地面以 45° 斜向铺开，建筑、货架、货柜、摊位都能同时看到**正面与顶面**；镜头略低，正面占比大。
- **为什么适合这个游戏**：货堆、翻看、抽取全部发生在货架**正面**（03 文档），仰视斜 45° 让玩家在店铺全景里就能直接看到每个货架的正面边缘条，不必切到单独界面；橱窗、模特的"对店外可见"也天然成立。
- **角色**：伪 3D 精灵，至少 4 向（推荐 8 向）行走帧，按 Y 轴深度排序（Godot `Y Sort`）；员工、客人、玩家共用同一套方向与帧规范。
- **实现要点（Godot 4）**：2D 场景 + 斜投影瓦片（正面高 h、顶面深 d 的两段式瓦片）+ `Y Sort`；可行走区域用斜向网格，屏幕坐标 = 网格坐标经 45° 斜变换；设备（§4.9）贴图同样提供正面 + 顶面两部分。抽取小游戏在货架正面视图上进行，与全景视角一致。
- **第一人称视角评估（2026-10-21，结论：不采用）**：Godot 4 自带完整 3D，做第一人称**不需要换引擎**，所以引擎不是理由；不采用是设计与成本上的判断。(1) 这个游戏的乐趣有一半在"一眼看全店"：几个客人在等、哪个货架塌了、员工在摸鱼，第一人称把这些全藏到视野外，管理感变成找路感。(2) 体力感最强的环节（翻看、抽取、开车、面对面讲价）本来就在**正面特写**里完成，已经是"准第一人称"，全景 + 特写两层比纯第一人称更兼顾。(3) 第一人称意味着放弃像素风、改做 3D 资产，独立开发工作量翻几倍，并丢掉已完成的斜视角代码。**折中**：保留开罗式全景作主视角，把特写环节（抽取、翻看、讲价、开车）做成第一人称式的近景面板；阶段 0 试玩后若仍觉得不够沉浸，再在 Godot 内评估 3D，不换引擎。

### 4.1 库存物理模型（公共底座）

所有模块的读写方。概念：

- **Item**（围巾）：SKU + 可空的品质状态（仅品质开关开启时存在，见 05 文档）
- **Box**（箱子）：装一组 Item，有容量、有外部标签（认知层）、有破损/受潮状态
- **Stack**（货堆）：槽位里的内容是一个**有序的货堆**（下标 0 为底部），有最大高度、混乱度、位移标记和倒地货物列表。抽取、翻看、倒塌、理货全部围绕它展开，详见 [03-货堆与抽取.md](03-货堆与抽取.md)。
- **Slot**（槽位）：持有一个 Stack 的位置。类型：
  - `WarehouseShelf` 仓库货架格
  - `ShopBackroom` 店内仓库格
  - `ShopDisplay` 店内展架格（有**展示度**属性：位置决定被客人看到的概率）
  - `CarTrunk` 车后备箱格
  - `StallTable` 摊位桌面格（摆摊阶段）
  - `Bag` 玩家随身行囊（摆摊阶段的物流与残货存放，容量有限，跨旬持久）
- **Location**（场所）：一组 Slot + 环境属性（湿度、面积、租金）

槽位之间的距离决定**拿取时间**：玩家走过去、翻看、抽取。整理得好 = 常卖的货靠近收银、放在堆的上层、同类相邻、标签准确。抽取下层货物要玩抽取小游戏，操作不当会让上方货物位移或倒塌（03 文档）。

### 4.2 趋势 / 经济模块

> 经济状态如何逐项决定进货价、运费、房租、工资、利率、消费能力与税务，见 [09-经济周期与价格体系.md](09-经济周期与价格体系.md)（2026-10-21 起以 09 为准）。本节只保留双循环与趋势的定义。

三层隐藏参数，都在真相层，最终加算得到本旬的有效经济状态：

```
E(t) = Base(year(t)) + C(t) + Season(t)
```

**a) 完整周期循环 Base —— 每 36 旬一次**
- 每到新的一年，宏观参数集（`consumption_level` 消费水平、`material_bias` 材质偏好、`wholesale_credit_risk` 批发拖账倾向、`loan_rate_base` 基准利率……）做一次**随机调整** Δ_k。
- Δ_k 的分布**只**取决于以往各年的 Δ_1 … Δ_{k-1}（例如：连续两年上行后下行概率增大，或带轻微惯性），**不**看旬级数据。
- 实现：`Base_k = Base_{k-1} + Δ_k`，`Δ_k ~ f(Δ_history) + noise`。`Δ_history` 存档保存。

**b) 连续周期循环 C —— 每旬一次**
- 每旬到来时，根据**最多前 36 旬**的经济状态与变化量，用一个指数衰减加权函数计算：
  ```
  C(t) = Σ_{i=1..36} w_i · x(t−i),   w_i = λ^i / Σλ^j,   0 < λ < 1
  ```
  `x(t−i)` 是第 t−i 旬的观测向量（实际成交量、成交均价、客流、拖账率等的变化量）。越往前的旬权重越小，λ 建议 0.85–0.92 起步，让约 10–15 旬前的影响衰减到可忽略。
- Base 与 C **互相独立**：C 只读历史观测，不读 Base；Base 只读年度 Δ 历史，不读 C。两者最后相加。
- 这样玩家自己的经营行为（卖得多、卖得贵）会通过 C 缓慢反馈回市场，但不会改变年度大势。

**c) 季节层 Season —— 每 9 旬换季**
- 四季各有一个材质偏好基线（例：春 真丝/棉麻；夏 冰丝/薄纱；秋 羊毛/羊绒；冬 羊绒/加厚针织）。
- **换季过渡**：季节边界前后各 1 旬做线性插值，而不是硬切换，这样"换季时流行的材质在变"是可感知的窗口。
- 季节层叠加在 Base 的 `material_bias` 上。

**d) 时尚趋势 Trend —— 颜色与图案**
- 一个随时间漂移的**隐藏需求向量**，维度：颜色、图案（可扩展：价位段）。材质维度不在这里，由上面三层决定。
- 客人生成时从 E(t) 决定的预算与材质偏好、Trend 决定的颜色与图案偏好中采样。
- 漂移模型：缓慢随机游走 + 偶发跳变（"突然流行格纹"）。
- 洞察时尚技能 = 对未来 Trend 向量的带噪预报；后期可加"经济嗅觉"技能对 E(t) 做带噪预报。

### 4.3 客人 AI

每位客人一个 Profile（真相层）+ 一个对话状态机：

- 类型：零售 / 批发
- 偏好向量（从趋势采样 + 个人偏差）
- 心理价位、议价策略（直接要折扣 / 装作要走 / 拉锯）
- 耐心、购物意向、犹豫度（"缠着问"的客人 = 高犹豫 + 高耐心）
- 信用（批发客人：按时付款概率、拖账天数分布）
- 善意（手动算账算错时会不会提醒）

状态机（2026-10-21 修订）：进店 → 浏览（受展示度影响）→ 询问 → 议价 → **成交 → 等货（玩家手动找货交付）→ 交付** → **继续购物（回到浏览，带同次购物上下文）/ 离开** → （批发）账期 → 付款/拖欠。任一步耐心耗尽都会离开。**完整的客人行为流程（停留、挑选、问价、拉扯、再逛、等待自取）、预期值向量与性格建模见 [06-客人行为与议价.md](06-客人行为与议价.md)，2026-10-21 起以 06 为准。**

**同次购物上下文** `VisitContext`（真相层，客人离开即销毁）：
```
VisitContext
  basket_count: int          # 本次已买几件
  spent: float               # 本次已花
  rapport: float (−1..1)     # 本次好感：成交价越接近他的心理价、议价选项越客气，越高；被怼、被宰越低
  wrong_deliveries: int      # 被递错货的次数
```
- **继续购物概率**：`continue_p = intent × f_budget(剩余预算) × (0.5 + 0.5·rapport) × (1 − 0.3·hesitation)`；常客额外 +。继续时回到浏览，重新挑货，耐心部分恢复。
- **价格标准波动**：下一件的心理价 `reserve' = reserve_base × (1 + ρ·rapport) × (1 − δ·g(basket_count))`，`g` 随件数递增趋于饱和。ρ、δ 由性格决定：`kindness` 高、常客（`visits` 多，"熟了"）→ ρ 大，**因为熟悉给个好价**（心理价上浮、`accept_tolerance` 变宽、议价回合更少）；`haggle_strategy = direct_discount`、`kindness` 低 → δ 大，**买多要求优惠**（心理价下压，开口就是"买两条便宜点吧"）。两个方向可以同时存在，净效果由该客人的参数决定，玩家只有【客人观察】Lv4（性格）才能预判方向。
- 剩余预算 `budget_mult` 随 `spent` 下降，是继续购物与心理价的共同上限。
- **交付出错**：递错货（`wrong_deliveries` +1）`rapport` 明显下降；第二次递错直接离开，常客的 `return_probability` 再扣。
- **当前实现值（PR #11）**：`ρ = 0.05 + 0.15·kindness + 0.1·min(visits, 6)/6`；`δ = 0.04 + 0.12·(1 − kindness)`，`direct_discount` 再加 0.1；`g(n) = 1 − e^(−0.67n)`；单次逛摊总预算 = `budget_mult × 3 × 首件基准价`，心理价不超过剩余预算；常客 `continue_p` 额外 +0.1；递错一次 `rapport −0.3`。

**常客与回购率**（`CustomerRegistry`）：客人分为持久的**常客**（有 ID、跨旬存在）和一次性的**过路客**。每次成交按 `(实付价 − 心理价) / 心理价` 调整该常客的 `return_probability`；宰客短期赚钱、长期流失。客人观察 Lv5 可见其先天回购倾向，口才 Lv6 提升回购率。详见 02 文档 §2.3。

### 4.4 员工 AI

**信息分层**（与 §2 两层世界一致）：

| 明面（认知层直接可见） | 隐藏（真相层） |
|---|---|
| 体能数据（体力上限、搬运速度、耐久） | 真实性格：勤奋度、诚实度、隐藏缺点（贪、懒、粗心、记仇……） |
| 薪资期望 | 当前心情、薪资满意度的真实值 |
| 已学技能等级 | `misconduct_log`：实际发生过的摸鱼、回扣、偷货 |

**玩家获取隐藏信息的三条通道**：
1. **员工观察技能**：对真实性格的带噪采样，等级越高越准（§2.2）。
2. **行为线索**：员工对不同工作指派会有可观察的反应（表情、一句台词、接受/推脱、完成质量）。反应由真实性格驱动但带随机噪声，所以玩家可以"看人"，但不能百分百确定。实现上是 `ReactionTable[flaw][task_type] → 一组带权重的可见反应`。
3. **自己记账比对**：玩家凭记忆（或游戏外的笔记）比对进货价、库存数与员工上报数。**游戏内不提供自动对账**，这是刻意的：对账能力本身是要用技能买回来的信息。

**对账能力由【数学能手】提供**（Lv2：知道有无出入；Lv5：知道具体哪一笔、差多少；仅在开启"员工贪腐"时有意义）：
- 未习得：账本只显示员工上报的数字，游戏不做任何异常提示。
- 实现：认知层 `Ledger` 与真相层 `TruthFinance` 做 diff，技能等级决定 diff 结果向玩家暴露的粒度。详见 02 文档 §2.5。

**员工技能与自称**：员工有自己的技能；玩家在员工观察 Lv4 之前只能看到员工**自称**的等级（爱摸鱼者倾向报低，爱表现者倾向报高），谈心有概率得知真实水平。
**满意度**：薪资满意度决定上下限，互动、工作量、当前心情、累积心情、心情趋势加权后夹在上下限内。公式见 02 文档 §5。

**处置动作**（玩家可随时对任一员工发起，不需要"先发现"）：

| 动作 | 前置 | 对该员工 | 对其他员工（旁观） | 对玩家 |
|---|---|---|---|---|
| 谈心 | 无 | 有概率揭示真实技能 / 部分性格；**提升满意度、降低摸鱼概率**（性格驱动的摸鱼除外）；同旬多次递减 | 无 | 消耗时间 |
| 批评 | 无 | **无论是否有根据，心情必降**；若其确有过错，可能短期收敛 | 心情小幅下降；若公认有理则威慑 | 无 |
| 罚款 | 无 | **无论是否有根据，心情必降**，薪资满意度下降；有过错者可能收敛 | 同上 | 收回罚款金额 |
| 开除 | 无 | 直接失去该员工 | 心情下降；若公认有理则影响小 | 可能需要赔偿（按合同） |
| 报警 | 需选择理由（如【盗窃】） | 属实：员工被带走，追回部分损失 | 属实：威慑；不属实：严重恐慌 | **不属实：玩家被拘留 7 天（店铺无法营业）并罚款** |

- "属实"的判定直接查真相层 `misconduct_log`，玩家永远看不到这个判定依据。
- 拘留 7 天不是单独的惩罚脚本，而是让时间推进 7 天且 `Player.available = false`：租金照扣、贷款照到期、仓库照样受潮（如开启）、批发账期照样过期。惩罚通过现有系统自然级联，不用另写逻辑。
- 谈心、批评、罚款、开除属于**必定内容**（摸鱼本身就需要管理）；报警只在开启"员工贪腐"时出现。

### 4.5 财务与信誉

- 现金流、应收（批发赊账）、应付（供应商账期，后期可加）
- **信誉分**：**开店后才开始积累**，摆摊阶段不存在信誉，只看现金。由收入稳定性、还款记录、拖账处理驱动
- **借贷**：可借额度 = f(信誉分, 近期收入)；**每 3 旬（一个月）还一期**；逾期扣信誉
- 账本：认知层的财务视图，员工贪腐时与真相层不符

### 4.6 物流 / 开车

- 两种方式并列：**自驾**（开车小游戏）与**委托物流公司**（实体，隐藏参数：价格、速度、受潮率、颠簸率、索赔政策）。
- 开车小游戏：独立模块，输入：路线、载货清单；输出：耗时、油费、**对箱子的运输事件**（受潮 / 颠簸，仅在品质开关开启时作用于品质）。
- 架构上完全隔离，可以替换或跳过（员工代驾 = 不进小游戏，按员工驾驶技能掷结果）。
- 路线规划：地图上的几个节点（托运部、仓库、店铺、家），不同路线耗时和风险不同。

### 4.7 技能系统

- 经验来源：经营时间、成交量、特定行为（整理、议价成功、追回欠款）
- 每个技能多等级，效果全部表现为**认知层采样参数的改变**（§2.2）
- 玩家技能（8 项）：审美积累、强化记忆、客人观察、员工观察、数学能手（跨技能修正器 + 对账 + 快速算账）、口才、驾驶、**吆喝（仅摆摊阶段）**。各级效果见 [02-技能与员工系统.md](02-技能与员工系统.md)。
- **分阶段解锁**：摆摊阶段各技能有等级上限（员工观察、驾驶锁定），开店后全开；另加少量前置依赖。见 02 文档 §7。
- 数学能手是**跨技能修正器**：每条认知提示带 `precision` 字段，其他技能决定有没有提示，数学能手决定精度上限。

### 4.8 剧情 / 随机事件层（预留，暂不实现）
- 不在当前计划内，但**保留占位与接口**：
  - `EventBus`：所有真相层状态变化发信号（成交、拖账、员工作恶被发现、趋势跳变……）。
  - `IEventSource` 接口：随机事件 / 剧情脚本作为事件源挂到总线上，可以读真相层、通过 ActionAPI 改世界。
  - 存档中预留 `events: {}` 字段。
- 现阶段只实现总线与接口，不写任何事件内容。

### 4.9 设备与道具（可购置）

玩家可以用现金购置设备。**架构上，设备 = 槽位提供者**：每件设备向当前 `Location` 注入一组 `Slot`，并可附带修正值。这样设备系统不需要新机制，直接复用 §4.1 的库存物理模型。

| 阶段 | 设备 | 提供的槽位 / 效果 |
|---|---|---|
| 摆摊 | 包（额外容器） | 追加 `Bag` 槽位，扩大行囊容量 |
| 摆摊 | 摊位板 | 追加 `StallTable` 槽位，提升每旬可展示的货物数量；更大的板占更大摊位面积，可能与商贩排他半径冲突 |
| 开店 | 货柜 | 追加 `ShopBackroom` 槽位（封闭，展示度 0，拿取较慢，容量大） |
| 开店 | 货架 | 追加 `ShopDisplay` 槽位（中等展示度，拿取快，容量中） |
| 开店 | 橱窗 | 追加少量 `ShopDisplay` 槽位（极高展示度），且**对店外可见**：影响过路客进店率，是开店阶段对应"吆喝"的硬件 |
| 开店 | 模特 | 1 个 `ShopDisplay` 槽位（最高展示度），所展示围巾的属性会放大对趋势匹配客人的吸引 |

- 每件设备有**占地面积** `footprint`；`Location.area_m2` 限制可放置总量，所以租更大的店和买更多货架是同一笔预算里的取舍。
- 设备位置由玩家在店内摆放，位置决定其槽位到收银台的路径（拿取时间）和被客人看到的概率，这与 §6.3 整理的逻辑一致。
- 设备可出售（折价）或在搬店时带走。
- 数据驱动：新增一种设备只加一条 `EquipmentDef` 记录。

## 6. 关键机制细化

### 6.1 进货
- 从供应商目录挑选 SKU 与数量；目录按批次刷新。
- 供应商（厂商）是实体，有隐藏参数（价格水平、品质缺陷率、退货政策、关系值）；品质开关开启后可选厂商更多。
- 摆摊阶段：从本地店铺进货，可与老板议价；开店后：从托运部 / 批发市场进货，量大价低但要自己运。
- 进货时只能看到 SKU 的外观属性，看不到趋势（除非有技能）。

### 6.2 仓储
- 租赁仓库：按地理位置的每平米价 × 面积。位置影响到店铺的物流距离。
- 地下仓库便宜但潮湿；无除湿机则货物品质随时间下降（进阶难度）。
- 店铺自带少量储存格；不租仓库就得自己从托运部搬回来。

### 6.3 整理
- 箱子在仓库格子化摆放；货物在店内仓库整包存放或拆包上架，上架后以**有序货堆**存在。
- 抽出的货物只能放回某堆**顶部**，不能插回原位，堆的混乱度会上升；**理货**可整堆重排，耗时与堆高成正比。
- 展架位置决定展示度；拿取速度由槽位到收银台的路径决定。
- 箱子外部无任何提示，玩家可手写标签（文字自由输入，这是认知层）。
- 强化记忆技能：最近 N 分钟内接触过的箱子/格子显示内容。

### 6.4 经营
- 客人进店后按展示度浏览；玩家须走到货架手动取货：先**翻看**边缘确认图案颜色（可能认错），再通过**抽取小游戏**或**从顶部拿取**取出（下层货物难抽、可能倒塌）。玩家不亲自拿时，客人自取或员工代拿按其属性采样出错概率，塌了会在店铺界面显示一地货。详见 03 文档。
- **成交后手动交付（2026-10-21 修订）**：讲完价不再自动出货。客人进入**等货**状态，带一个按耐心算的等待时间（约 `20 + 40·patience` 秒，口才 Lv5 减缓）。玩家要自己在货堆里**找到他要的那份**（靠记忆或翻看，可能认错），用拆顶或抽取把它拿到**手上**（03 §4），再**点击客人**才算交付、收钱。规则：
  - 手上有他指的那一份 → 交付成交；手上是**同款别的一份** → 同样接受（他要的是这个款）。
  - 手上只有别的款（翻看认错了）→ 客人说"不是这条"，`rapport` 下降、等待时间扣一截，货留在手上让玩家再找；第二次递错直接走人。
  - 手上没货点客人 → 只提示"他要的是……"（按玩家的认知层信息描述），不扣耐心。
  - 等待超时 → 客人离开，这单作废，计入"谈成没拿到货"的流失统计，常客 `return_probability` 下降。
  - 等货期间其他客人照常来问价，可以同时有多位客人在等货；每一次拆顶 / 抽取仍然走 03 文档的时间与倒塌结算。
  - 点击客人的含义按其状态而定：问价中 → 去讲价；等货中 → 交付；看货中 → 无动作（预留"招呼"）。
- **议价时始终显示成本价（2026-10-21）**：议价面板上一直显示客人所指那份货的**成本价**，即它的实际进货单价（来自该份货的 `provenance` 进价记录，含当时谈下来的折扣；没有记录的老货用当前本地进货价估算并标“约”；本期店里没有这款时取进价区间中值 `base_cost × 1.175`，PR #15）。「一起买」时两条各自的成本和合计都显示，任一条是估算则合计也标“约”。这是玩家自己的账，不走认知层、不受技能影响，目的是让每一次报价都能当场看到毛利。
- **连续购物**：交付后客人可能继续挑货（§4.3 `continue_p`），再次问价时心理价按同次购物上下文波动：熟了的、好说话的客人会给个好价，爱砍价的会"买多要优惠"。玩家多一个议价选项**「一起买给您算便宜」**（`basket_count ≥ 1` 时出现）：对篓子里全部货报一个总价，一次谈成多件，但失败会扣更多耐心。
- **当前实现值（PR #11）**：
  - 等货时间 `(20 + 40·patience)` 秒，口才 Lv5 时 ×1.25；递错一次扣 10 秒；超时离开常客回购率 −0.1，第二次递错再 −0.05。
  - "他要的是……"的提示记录的是**他指货那一刻**的位置（第几格摊位、从上往下第几份、露出什么颜色的边），之后货被挪动提示也不更新；等货期间不再用白框高亮那份货。找货靠的是玩家自己的记忆。
  - 「一起买」的具体做法：在他问的这条之外，从摊上再配一条他最喜欢的，两条报一个总价，上限为两条心理价之和；谈成后要**交两条**，按各自心理价比例分摊收钱。失败扣耐心 0.45，报价远超心理价时 0.6（单件分别是 0.18 和 0.3）。
- 议价对话（**混合式 UI**）：每轮玩家既可以选对话选项（"这是最低价了"、"再送您一条围巾带"、"那您看看别的"），也可以直接输入一个价格。选项影响客人情绪与耐心，价格影响成交判定。两条路径都走同一个 `HaggleState`，保证以后随意增删选项不影响数值。
- 手动结账（进阶难度）：用游戏内计算器逐项算；算低了自己亏（善意客人会提醒），算高了事后被追究（扣信誉）。
- 批发客人：大单、低价、可能赊账。

### 6.5 员工
- 中期解锁。可委托：进货、仓储、整理、经营、开车。
- 招聘界面只展示体能数据、薪资期望、已有技能；性格完全隐藏。
- 摸鱼 / 贪腐 / 偷货机制见 §2.3、§4.4。
- 发现方式：自己记账比对（无自动对账）、员工行为线索、客人投诉、员工举报、员工观察技能、数学能手 Lv2/Lv5 对账。
- 处置动作及其风险见 §4.4 表格；误报警的代价（拘留 7 天 + 罚款）是整个员工系统最重的惩罚，也是"没把握不要动手"的核心张力。

### 6.6 技能
- 见 §4.7。所有技能效果通过认知层参数实现。

### 6.7 信誉与借贷
- 摆摊阶段只有现金，没有信誉也不能借贷；开店是信誉的起点。
- 没有硬性破产。开店后现金为负时可借贷；借贷额度与利率由信誉分决定（利率还叠加 Base 的基准利率）。
- 还款节奏：每 3 旬还一期，与租金、工资同一结算日。
- 信誉分来源：按时还款、按时付供应商、处理客人投诉、结账准确率。
- 信誉过低 → 借不到钱 → 现金断流 → 事实上的游戏结束（软失败），但不强制重开。

### 6.8 必定内容 vs 可选难度

**必定内容**（基础游戏一定包含，不可关闭）：
- 进货：挑选 SKU、规划数量、隐藏的时尚趋势与宏观经济
- 仓储：租仓库（位置 × 面积定价）、店铺自带少量储存
- 物流：自己开车送货、路线规划、开车小游戏
- 整理：仓库箱子摆放、店内上架、展示度与拿取速度、箱子手写标签、外部无提示
- 经营：讲价客人、低意向客人、缠问犹豫客人、批发/零售、每人各自心理价、手动从货架拿货
- 技能系统：多等级、认知层采样
- 员工：中期雇佣、代劳手动环节、**会摸鱼**（受心情与薪资满意度影响）；体能与薪资期望明示、性格隐藏；谈话 / 批评 / 罚款 / 开除四种处置
- 摆摊前期阶段（阶段 0）
- 信誉分 + 借贷分期

**可选难度开关**（默认关闭；完整定义见 [04-进阶难度选项.md](04-进阶难度选项.md)）：
- **品质**（总开关，详见 [05-品质系统.md](05-品质系统.md)），附属开关：霉菌、平整、错织、错染。总开关打开则附属全开；附属至少保留一个。基础游戏中围巾没有品质概念。
- 手动结账（游戏内计算器逐项算；算低自亏、善意客人提醒；算高被追究）
- 员工贪腐（收回扣、偷货；无自动对账，需【数学能手】Lv2/Lv5；新增【报警】处置，误报则玩家被拘留 7 天并罚款）
- 批发客人拖欠付款、需催账；同时使厂商退款与物流赔付延期

> 注意区分：员工**摸鱼**是必定内容，员工**贪腐**是可选难度。

### 6.9 摆摊阶段（阶段 0 的玩法定义）

一旬的循环：**【进货】→【寻找摆摊位置】→【开始经营】→【将卖不完的带回去】**。

**进货**：从本地店铺进货，可与老板议价（口才生效）。只能看到外观属性。

**寻找摆摊位置**（`StreetScene`）：
- 玩家在一个街区上行走。街区有一个**人流场** `TrafficField`：不同路段的过路客生成密度不同，随旬内时段、季节（后期可加天气）变化。人流密度不直接显示，玩家靠观察路上的行人多少来判断。
- 街上有若干**已在摆摊的商贩** `VendorNPC`，各有一个**排他半径**，玩家不能在其内摆摊。商贩位置本身就是"这里人多"的信号，所以选址是人流 vs 竞争的权衡。
- 玩家确认位置后进入经营。

**开始经营**（`StallArea`）：
- 一定距离以外的区域被屏蔽，只显示玩家周遭 **N×M** 的区域（N、M 由吆喝等级决定，见 02 文档 §2.8）。
- 过路客沿人流路径穿过该区域时掷一次**逗留判定**：`stay_p = base × 吆喝修正 × 偏好匹配度（看到摊位上的货与自己喜好的匹配） × 展示度`。逗留后进入正常的客人状态机（浏览 → 询问 → 议价 → 成交 / 离开）。
- 屏蔽区域外没有任何信息：玩家不知道旁边商贩卖得怎样。
- **卖光自动收摊（2026-10-21）**：营业中若摊位、手上、行囊**全部为空**，且没有正在讲价或等货的客人，提示"卖光了"后数秒自动收摊进入结算（结算页标记"卖光"）。若摊位空了但**行囊里还有货**，不自动收摊，只提示"摊上空了，从行囊补货或收摊"，由玩家决定。自动收摊前有 3 秒实时倒计时（PR #11）。

**将卖不完的带回去**：
- 未售出的货物留在**行囊** `Bag`（一种 `Slot` 容器，容量有限）里，持续占位。
- 玩家可以**随时丢弃**，或在未来任意一旬**再次摆出**。
- 行囊容量 + 进货量 + 卖不完的残货，三者共同构成摆摊阶段的"仓储压力"，是开店后仓库系统的雏形。

**阶段过渡**：摆摊阶段只看现金；达到资金门槛（数值待定）后可选择开店，进入阶段 1。开店是信誉的起点（§6.7）。吆喝等级在开店时一次性转化为店铺的初始客流量加成（独立加成项，见 02 文档 §2.8）。

## 7. Godot 项目结构建议

```
res://
├── core/                 # 纯逻辑，不依赖场景，可单元测试
│   ├── truth/            # 真相层：Inventory, Trend, CustomerProfile, Employee, Finance
│   ├── knowledge/        # 认知层：Label, Memory, Sampler, Ledger
│   ├── actions/          # ActionAPI 及其实现
│   ├── ai/               # CustomerFSM, EmployeeAgent
│   └── sim/              # 时间推进、旬末结算、趋势漂移、经济循环
├── data/                 # .tres 资源：SKU 表、技能表、客人原型、供应商目录
├── scenes/
│   ├── stall/            # 摆摊场景（第一个 vertical slice）
│   ├── shop/
│   ├── warehouse/
│   ├── minigames/
│   │   ├── driving/      # 开车
│   │   └── pull/         # 抽取货物（03 文档）
│   └── ui/               # 结算、账本、计算器、技能树
├── tests/                # GUT 或 gdUnit 单元测试，覆盖 core/
└── docs/                 # 本文及后续设计文档
```

原则：`core/` 不 `extends Node`，不引用任何场景；场景只读 Knowledge、只调 ActionAPI。这样数值与 AI 可以在无 UI 下跑模拟与测试。

### 7.1 存档与版本迁移（硬约束）

更新会相当频繁，**任何版本都不能让旧存档失效**。方案：

1. **格式**：存档用 **JSON**（或 Godot 的 `var_to_str`/`JSON.stringify` 字典），**不要**直接序列化 `Resource`/`PackedScene`。二进制 Resource 一旦脚本改名、字段改类型就直接读不回来；JSON 字典可以手工迁移。
2. **版本号**：存档根节点带 `schema_version: int`，每次改存档结构 +1；游戏内常量 `CURRENT_SCHEMA_VERSION`。
3. **迁移链**：`core/save/migrations/` 下每个版本一个文件 `m_0001_to_0002.gd`，只负责把 N 版字典改成 N+1 版。加载时从存档版本逐级跑到当前版本。迁移函数只能增字段、改名、换默认值，不能依赖游戏逻辑。
4. **前向兼容**：加载时**保留未知字段**不丢弃，写回时原样带上；新增字段一律有默认值。这样大部分小改动根本不需要迁移脚本。
5. **稳定 ID**：SKU、技能、客人原型、槽位类型等全部用字符串 ID（`"scarf_plaid_red_wool"`），不用数组下标或枚举整数；这样改数据表顺序不会错位。
6. **回归测试**：`tests/save_fixtures/` 保存每个历史版本的一份真实存档；CI 里逐个加载并断言迁移后能正常跑一旬模拟。每次提升 `schema_version` 必须新增一份 fixture。
7. **备份**：写存档前先把旧文件改名为 `.bak`，迁移失败时提示玩家并保留原档，绝不覆盖。
8. **Godot 版本**：Godot 4.x 小版本升级也可能影响序列化，所以更要坚持 JSON 字典 + 自己的迁移链，不依赖引擎序列化格式。

## 8. 开发路线

### 阶段 0 · 摆摊 Vertical Slice（第一个可玩版本）
摆摊是整个循环的最小完整版本，没有仓库、车、员工，但两层架构、库存模型、客人 AI 必须在这个阶段就建对。

玩法定义见 §6.9。包含：
- 从本地店进货（含议价）
- 街区选址：人流场、其他商贩的排他半径
- 行囊运货到摊位；卖不完的留在行囊，可丢弃或下旬再摆
- 摊位 N×M 周遭区域、过路客逗留判定
- 摊位桌面格子化摆放（展示度）；摊位上为浅货堆（高 2–4），验证翻看与抽取小游戏
- 可购置的包与摊位板（设备 = 槽位提供者，验证 §4.9）
- 零售客人：浏览、询问、议价、成交
- 实时一旬 + 旬末结算；季节已生效（换季材质变化在摆摊阶段就能看到）
- 只有现金，无信誉、无借贷
- 技能：吆喝（全部）、口才 ≤3、客人观察 ≤2、审美积累 ≤2、强化记忆 ≤2、数学能手 ≤1，验证认知层采样机制与阶段门

### 阶段 1 · 开店
- 店铺场景、店内仓库、展架、手动取货
- 可购置设备：货柜、货架、橱窗、模特（占地面积受店铺面积限制）
- 托运部进货 + 开车小游戏 + 路线

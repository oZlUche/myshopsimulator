## 0. 这个子系统在设计支柱里的位置

现实中围巾叠放受重力挤压：下面的难抽，硬抽会把一片货弄塌；外面只看得到边缘，容易认错。这正是总览 §1 "信息不透明 + 体力成本"的最直接体现：

| 不透明 | 体力 | 买回来的方式 |
|---|---|---|
| 只看到边缘，可能认错 | 必须逐份翻看 | 强化记忆（文本显示） |
| 不知道抽这一份会不会塌 | 抽取小游戏；或从顶部一份份拿下来（零风险但费时、打乱顺序） | 抽取技能（待命名）、员工代劳 |
| 抽出来放不回原位，顺序会乱 | 重新理货 | 整理规划、员工代劳 |

## 1. 货堆模型

每个可展示 / 可存放的 `Slot` 不再是"放一个箱子或一件货"，而是一个**有序的货堆** `Stack`：

```
Stack
  slot_id
  items: [ScarfItem]          # 下标 0 = 最底部，末尾 = 顶部
  max_height: int             # 由设备（货架 / 货柜 / 摊位板）决定
  disorder: float (0–1)       # 混乱度：顶部与底部顺序、同类是否相邻等的综合
  displaced: bool             # 上方堆是否位移、遮住了下方
  collapsed_pile: [ScarfItem] # 倒在地上的货；非空时该槽位前方显示一堆货
```

- 玩家从**正面**看一个货堆，只看到每份货露出的**边缘条**（见 §3）。
- 箱子 `Box` 仍然存在于仓库与运输环节；上架时箱子被拆开，围巾逐份进入 `Stack`。仓库里的箱子堆也可以复用同一套 `Stack` 逻辑（箱子为单位），但抽取与翻看规则只在围巾堆上启用。
- 摆摊阶段的摊位板上同样是货堆，但 `max_height` 很小（2–4），保证阶段 0 就能验证这套机制而不会过于折磨。

## 2. 抽取小游戏

### 2.0 设计重点（2026-10-21 定稿）

- **重点是"抽不好会塌"，不是"抽不出来"。** 抽出本身必须是稳稳能做到的事：只要一直拖，货物一定会被带出（`v_item` 永远大于 0，上方重量只让它变慢，不会卡死），不存在"怎么拖都拖不出"的挫败。小游戏的全部张力放在**倒塌 / 位移判定**上：抽得糙，上面那一摞就塌一地。
- 因此参数分工明确：`k_w`（压迫系数）只决定**时间成本**，`α β γ`（倒塌公式）决定**风险**。调参时不要用"抽不动"来制造难度。
- 玩家的决策不是"能不能抽出"，而是**"从中间抽（快、有风险）还是从顶部一份份拿下来（慢、零风险、但拿下来的货只能放到别的堆顶，顺序会乱）"**，以及"抽的时候花多少时间小心"。
- **两种拿法，按点击位置区分**：
  - **点顶部**（堆最上面那份的顶面）= **从顶部拿取**：拿起最上面一份，没有小游戏、不会塌，固定耗时短；连续点击就一份份往下拿。
  - **点侧面**（某份货露出的边缘条）= **抽取**：进入小游戏，有塌的风险，但一步到位、不打乱别的堆。
  - 对堆顶那一份，两种点法等价：`N = 0`，直接拿，不开小游戏。
- NPC 同样有这两种拿法：谨慎的员工 / 有耐心的客人倾向拆顶，马虎的直接从中间抽（§5）。
- **一次拿多份**（2026-10-22）：按住左键拉框选中连续几份再松手，就是上面两种拿法的批量版（§2.6）。能一次拿几份由「手上」的余量决定，而手上的上限由【搬运】技能决定（§4）。

### 2.1 操作

**从顶部拿取**：点击堆顶货物的顶面，最上面一份进入玩家手中，耗时固定（约 0.5 秒 / 份，营业中计时），不做任何判定。拿下来的货遵守 §4 的放回规则（只能放到某个堆的顶部）。

**抽取**：点击堆中第 `i` 份货（从底算起）的侧面边缘条，进入抽取界面：
1. 选择**发力点**：货物的某个**角落**（最佳）或边缘中部（次佳）。
2. 按住并**拖动**：拖动方向与水平面的夹角 θ，最佳为斜向（约 30°–45°）。
3. 拖动过程中的**速度曲线**：最佳为**先慢后快**（先松动再带出）。

**位移规则（2026-10-19 修正）**：
- 货物**不会缩回去**：每次拖动带出的距离都累计在 `pulled_fraction`（0–1，相对货物长度）上，松手后保持原位，露出的部分一直可见。
- **累计抽出一半（`pulled_fraction ≥ 0.5`）即算成功**，货物脱离货堆进入玩家手中。
- 可以分多次拖动完成一次抽取；每一段拖动独立计算偏差分 `d` 并各自掷一次倒塌 / 位移判定（§2.2），所以"慢慢多拖几次"更安全但更耗时。
- 抽取中途离开（去接待客人等），半抽出的货物保持半露状态，之后可以继续。

### 2.2 公式

记 `N = 目标货物上方的份数`，`W = 上方总重量（按材质加权）`。

**拉动速度**（货物实际跟随手的速度，手的速度为 `v_hand`）：

```
v_item = v_hand · 1 / (1 + k_w · W) · f_angle(θ) · f_point(p)
```
- `k_w`：压迫系数。上方越重，货物越"跟不上"手，玩家会感到阻滞。
- `f_angle(θ)`：θ 在 30°–45° 时为 1，水平或垂直硬拉时降到 0.4–0.6。
- `f_point(p)`：角落 1.0，边缘中部 0.7，中央 0.4。

**偏差分** `d`（0 = 完美，越大越差）：

```
d = a · |θ − θ*|/θ*                       # 角度偏差
  + b · (1 − f_point(p))                  # 发力点偏差
  + c · max(0, v_hand(早期) − v_slow)      # 起手太快
  + e · jerk                              # 速度突变
```

**倒塌概率**（每一段拖动结束时判定一次，见 §2.1 位移规则）：

```
p_collapse = sigmoid(α · d + β · N − γ)
```
- 没有上方货物（N = 0）时不会塌（从顶部拿取也走这里，`d = 0, N = 0` 必然安全）；N 越大、d 越大越危险。
- **当前实现值（PR #10）**：跟手比例有下限 `MIN_FOLLOW = 0.3`（再重也至少以手速的 30% 跟出，保证一直拖必能抽出）；`α β γ = 3.5 / 0.4 / 6.0`：小心抽（d ≈ 0）压 6 份时塌的概率约 4%，抽得糙（d = 1.5）压 2 份时约 51%。
- 调参约束（§2.0）：`γ` 要足够大，使 `d` 很小时即便 N 较大也基本不塌，让"小心抽"真正有回报；`α` 要足够大，使 `d` 大时 N ≥ 2 就有明显风险。

**位移**（未倒塌时）：

```
shift = d · N · s
若 shift > 阈值 → Stack.displaced = true，上方堆遮住下方若干份
```

**倒塌结果**：目标货物上方全部（或按 N 的一部分）进入 `collapsed_pile`，槽位前方显示一地货；这些货需要玩家或员工**拾起并重新上架**（§5）。

### 2.3 技能钩子（待命名，暂称【抽货】）

- 作为第 9 项玩家技能预留，摆摊阶段可学（摊位上也要抽货）。
- 效果类型：放宽最佳角度区间、降低 `k_w`（更容易带动）、降低 `α`（同样偏差更不易塌）、高等级显示"安全抽取提示线"。
- 详细等级表留待后续补充到 02 文档。

### 2.4 抽出后剩余货堆的状态

- 抽出成功后，**剩余货物的摆放状态原样保留**：不自动下沉填补空位、不重排顺序。上方货物若有位移（`displaced`）就保持位移，玩家看到的货堆就是真实的物理结果。
- 空隙只在下一次操作（放顶、理货）时才会被改变。这样整理的后果是可见、可累积的，与"整理决定效率"的设计一致。

### 2.5 抽取数据

抽取进度**挂在每一份货上**，而不是以槽位索引为键挂在 Stack 上：抽走、倒塌都会改变货物在堆里的索引，按索引存会错位。

```
ScarfItem 增补（已实现，PR #5 / #7）
  pull_out  : float   # 累计抽出比例（占货长，带方向 ±），|pull_out| ≥ 0.5 即抽出
  shift     : float   # 被下方抽货带歪的横向位移（占货长，±），理货时才归位
  gap_below : int     # 下方被抽走的货留下的空隙层数；放顶 / 拾起时压实，理货归位
```

- 每段拖动的偏差分 `d` 只用于当段的倒塌 / 位移判定（§2.1、§2.2），不跨段累计，所以不存。
- 存档：只有动过的货才写入可选字段 `pull: {out, shift, gap_below}`；老存档读入时全部为 0，**不需要升 schema**。
- 空隙记在货物上而不自动下沉（§2.4）。

### 2.6 框选：一次选多份（2026-10-22）

**手势**：在一个货堆上按住左键并拖动超过 6 px 就开始拉框（半透明矩形），松手结算；移动不足 6 px 仍是原来的单击。右键拉框是翻看。Esc 或点空处取消。

**选中了什么**：框与之相交的边缘条都算选中；在一个堆内只取**连续的一段** `[lo, hi]`（相交的最低份到最高份之间全部算，中间漏框的也补上，因为实际上没法越过中间那几份）。光标旁显示「选中 n 份 · 手上还能拿 k」。阶段 0 只做**单堆内**框选，框拖出堆外按本堆算；跨堆框选留给店面阶段地上的箱包（07 §2.1）。

**松手后做什么**，按这一段包不包含堆顶分两种：

| 情况 | 动作 | 规则 |
|---|---|---|
| 段含堆顶（`hi` = 最上面那份） | **批量拆顶** | 从顶往下逐份进手上，每份 `TAKE_TOP_SECONDS`（0.5 秒，【搬运】Lv2 ×0.8）；不判定、不会塌。实际拿的数量 = `min(n, 手上余量)`，拿不完提示「手上只能再拿 k 份」 |
| 段不含堆顶 | **整块抽取** | 开一次抽取小游戏，把这 n 份当一块抽。`N`（上方份数）同单份；时间成本里的压迫项 `k_w` 乘 `1 + 0.25·(n−1)`（块更重）；倒塌系数 `α` 乘 `1 + 0.2·(n−1)`（块厚，上面更容易被带动）；位移规则同单份；成功后 n 份按原顺序一起进手上，下面留 n 层 `gap_below`。块必须 ≤ 手上余量，否则不能开始（提示先放下） |
| 右键拉框 | **批量翻看** | 对选中的每份依次 `peek_item`，每份 2 秒，结果写认知层；不受手上限制 |
| 在「手上」槽里拉框 | **批量放下** | 选中 k 份后点某一格的空处，k 份按原顺序依次放到那堆顶（每份 0.5 秒），放不下的留在手上。没有选中时点格 = 放一份（原行为） |

- 批量拆顶与单击拆顶是同一个动作重复 n 次，所以 `disorder`、强化记忆的"最近触碰"都按 n 次记。
- 整块抽取仍然遵守 §2.0：一定抽得出，风险在塌；块越厚风险越高是故意的，让"一把抓三条"比"一条条抽"更刺激也更危险。
- NPC 不框选：`npc_fetch` 仍是逐份；员工一次搬多件由其搬运技能决定（02 §3，待补）。

## 3. 翻看

- 面对货堆时，每份货只露出一条**边缘条**。要确认图案和颜色，必须点击边缘进行**【翻看】**，掀起一角看到一小块区域。
- 翻看得到的是**部分信息**：
  - 纯色围巾：几乎不会认错。
  - 图案围巾：边缘区域可能只含图案的一部分；与库中其他 SKU 相似时存在**认错概率** `p_confuse(sku, visible_region)`，由 SKU 之间的视觉相似度表驱动。**实现（PR #12）**：相似度表在 `data/scarf_attributes.json` 的 `pattern_similarity`（与 06 文档 §2 客人挑选共用一张），认成图案 q 的概率 `= 0.32·sim(p, q)²`；纯色合计约 2%，格纹约 14%（多认成条纹），碎花约 10%。
  - 认错是认知层事件：玩家看到的是一个"推断出的 SKU"，真相层不变。
- 翻看消耗时间（营业中会被客人耐心惩罚）。
- **强化记忆**的作用在这里落地：对最近操作过的槽位，悬浮框直接以**文本**显示名称 / 颜色 / 数量（见 02 文档 §2.2），无需翻看、不会认错。
- 翻看后信息进入 `Knowledge`，带 `precision` 与 `may_be_wrong` 标记；数学能手不影响这里（它只修正数值类提示）。

## 4. 放回与顺序

- **抽出 / 拿下的货物不能插回原位**，只能放到某个堆的**顶部**。
- 从顶部一份份拿下来再拿目标货，是零风险换顺序混乱：拿下来的每一份都要放到别的堆顶（或手里暂存上限内），事后要么理货、要么接受 `disorder` 上升。这是 §2.0 取舍的另一半代价。
- **「手上」暂存槽 `Hand`**（PR #10）：拿下或抽出的货先进手上，**默认最多 3 份**；再点某个堆的空处放到堆顶。手上满了就拿不动，必须先放。收摊时手上的货自动回行囊。`Hand` 是用到时才创建的普通槽位，不升存档 schema。**开店后扩展**（07 §1）：手上要么 ≤3 条散货，要么 1 箱，要么 ≤3 包，三选一不能混拿。
- **上限由【搬运】技能决定**（2026-10-22，02 §2.10）：散货 3 → 4 → 5 → 6，包 3 → 4 → 5，箱 1 → 2，三选一的规则不变，每种形态按各自上限判断（不是统一折算单位）。`Inventory.hand()` 每次调用时按 `SkillSystem.carry_mods(player)` 重设 `max_height` / `pkg_capacity`，老存档里存的旧上限不作数。框选（§2.6）一次能拿的份数就是这个余量。
- **店里推着手推车时，车就是「手上」**（2026-10-22，07 §2.1）：所有"进手上"的动作改为进车（箱包 6 单位可混 + 散货篓 ≤10 条），点客人交货时车上有他要的那份也算"手上有"。代码上用 `ActionAPI.carrier()` 返回当前的 `Hand` 或 `Cart`，拿 / 放 / 交付都只认 `carrier()`。
- 每次放顶会改变堆的顺序，`disorder` 上升：同款被分散、颜色不连续、常卖款被压到底下。
- `disorder` 影响：
  - 下次找货需要翻看的次数（信息成本）
  - 平均 N（体力成本与倒塌风险）
  - 展示度（乱堆看着不吸引人，轻微负修正）
- **理货**：对一个槽位发起整理，把整堆取下按玩家指定顺序重新叠放。耗时与堆高成正比，营业中做会损失客流。员工可代劳（质量由其整理技能决定）。

## 5. 玩家不亲自拿货时

| 执行者 | 出错概率的决定因素 |
|---|---|
| **客人自取**（玩家忙于别处、或客人等不及自己上手） | 基础概率较高；性格【马虎】↑、耐心低↑、**头一次来**（不熟悉店里摆放）↑；常客↓ |
| **员工** | 由员工的整理 / 搬运技能等级决定；心情差、摸鱼时↑ |
| 玩家 | 由抽取小游戏的实际表现决定；从顶部拿取不判定 |

- NPC 拿法选择：客人耐心高、员工性格谨慎 → 更可能从顶部一份份拿（耗时长，但不塌，拿下的货随手放到邻近堆顶，`disorder` 上升）；马虎、没耐心、头一次来 → 直接从中间抽。

- "出错" = 按 §2.2 同样的 `p_collapse` 与位移规则结算，只是 `d` 不由玩家操作产生，而是从执行者属性采样。
- 出错结果在**整体店铺界面**上可见：对应货架 / 货柜前出现一地货物的贴图，玩家一眼能看到哪里塌了，但看不到塌的是什么（除非走过去看 / 有记忆信息）。
- 倒地货物在拾起前**不可售**，且会阻碍该通道的通行（拿取路径变长）。
- **品质**：品质开关关闭时，倒地**不影响品质**，拾起即恢复。开启品质附属开关**【平整】**（04 文档 §2.2、05 文档 §1.2）后，倒地货物的 `flatness` 百分比下降，须执行**【拉平】**`smooth_item` 恢复（恢复率与上限按材质），否则上架 / 售出时折价。

## 0. 这个子系统在设计支柱里的位置

现实中围巾叠放受重力挤压：下面的难抽，硬抽会把一片货弄塌；外面只看得到边缘，容易认错。这正是总览 §1 "信息不透明 + 体力成本"的最直接体现：

| 不透明 | 体力 | 买回来的方式 |
|---|---|---|
| 只看到边缘，可能认错 | 必须逐份翻看 | 强化记忆（文本显示） |
| 不知道抽这一份会不会塌 | 抽取小游戏 | 抽取技能（待命名）、员工代劳 |
| 抽出来放不回原位，顺序会乱 | 重新理货 | 整理规划、员工代劳 |

## 1. 货堆模型

每个可展示 / 可存放的 `Slot` 不再是"放一个箱子或一件货"，而是一个**有序的货堆** `Stack`：

```
Stack
  slot_id
  items: [ScarfItem]          # 下标 0 = 最底部，末尾 = 顶部
  max_height: int             # 由设备（货架 / 货柜 / 摊位板）决定
  disorder: float (0–1)       # 混乱度：顶部与底部顺序、同类是否相邻等的综合
  displaced: bool             # 上方堆是否位移、遮住了下方
  collapsed_pile: [ScarfItem] # 倒在地上的货；非空时该槽位前方显示一堆货
```

- 玩家从**正面**看一个货堆，只看到每份货露出的**边缘条**（见 §3）。
- 箱子 `Box` 仍然存在于仓库与运输环节；上架时箱子被拆开，围巾逐份进入 `Stack`。仓库里的箱子堆也可以复用同一套 `Stack` 逻辑（箱子为单位），但抽取与翻看规则只在围巾堆上启用。
- 摆摊阶段的摊位板上同样是货堆，但 `max_height` 很小（2–4），保证阶段 0 就能验证这套机制而不会过于折磨。

## 2. 抽取小游戏

### 2.1 操作

玩家选中堆中第 `i` 份货（从底算起），进入抽取界面：
1. 选择**发力点**：货物的某个**角落**（最佳）或边缘中部（次佳）。
2. 按住并**拖动**：拖动方向与水平面的夹角 θ，最佳为斜向（约 30°–45°）。
3. 拖动过程中的**速度曲线**：最佳为**先慢后快**（先松动再带出）。

**位移规则（2026-10-19 修正）**：
- 货物**不会缩回去**：每次拖动带出的距离都累计在 `pulled_fraction`（0–1，相对货物长度）上，松手后保持原位，露出的部分一直可见。
- **累计抽出一半（`pulled_fraction ≥ 0.5`）即算成功**，货物脱离货堆进入玩家手中。
- 可以分多次拖动完成一次抽取；每一段拖动独立计算偏差分 `d` 并各自掷一次倒塌 / 位移判定（§2.2），所以"慢慢多拖几次"更安全但更耗时。
- 抽取中途离开（去接待客人等），半抽出的货物保持半露状态，之后可以继续。

### 2.2 公式

记 `N = 目标货物上方的份数`，`W = 上方总重量（按材质加权）`。

**拉动速度**（货物实际跟随手的速度，手的速度为 `v_hand`）：

```
v_item = v_hand · 1 / (1 + k_w · W) · f_angle(θ) · f_point(p)
```
- `k_w`：压迫系数。上方越重，货物越"跟不上"手，玩家会感到阻滞。
- `f_angle(θ)`：θ 在 30°–45° 时为 1，水平或垂直硬拉时降到 0.4–0.6。
- `f_point(p)`：角落 1.0，边缘中部 0.7，中央 0.4。

**偏差分** `d`（0 = 完美，越大越差）：

```
d = a · |θ − θ*|/θ*                       # 角度偏差
  + b · (1 − f_point(p))                  # 发力点偏差
  + c · max(0, v_hand(早期) − v_slow)      # 起手太快
  + e · jerk                              # 速度突变
```

**倒塌概率**（抽取结束时判定一次）：

```
p_collapse = sigmoid(α · d + β · N − γ)
```
- 没有上方货物（N = 0）时几乎不会塌；N 越大、d 越大越危险。

**位移**（未倒塌时）：

```
shift = d · N · s
若 shift > 阈值 → Stack.displaced = true，上方堆遮住下方若干份
```

**倒塌结果**：目标货物上方全部（或按 N 的一部分）进入 `collapsed_pile`，槽位前方显示一地货；这些货需要玩家或员工**拾起并重新上架**（§5）。

### 2.3 技能钩子（待命名，暂称【抽货】）

- 作为第 9 项玩家技能预留，摆摊阶段可学（摊位上也要抽货）。
- 效果类型：放宽最佳角度区间、降低 `k_w`（更容易带动）、降低 `α`（同样偏差更不易塌）、高等级显示"安全抽取提示线"。
- 详细等级表留待后续补充到 02 文档。

### 2.4 抽出后剩余货堆的状态

- 抽出成功后，**剩余货物的摆放状态原样保留**：不自动下沉填补空位、不重排顺序。上方货物若有位移（`displaced`）就保持位移，玩家看到的货堆就是真实的物理结果。
- 空隙只在下一次操作（放顶、理货）时才会被改变。这样整理的后果是可见、可累积的，与"整理决定效率"的设计一致。

### 2.5 抽取数据

抽取进度**挂在每一份货上**，而不是以槽位索引为键挂在 Stack 上：抽走、倒塌都会改变货物在堆里的索引，按索引存会错位。

```
ScarfItem 增补（已实现，PR #5）
  pull_out   : float   # 累计抽出比例（占货长，带方向 ±），|pull_out| ≥ 0.5 即抽出
  pull_d_sum : float   # 各段拖动偏差分按抽出距离加权累计
  pull_w_sum : float   # 加权分母；平均偏差 = pull_d_sum / pull_w_sum
  shift      : float   # 被下方抽货带歪的横向位移（占货长，±），理货时才归位
```

- 存档：只有动过的货才写入可选字段 `pull: {out, d_sum, w_sum, shift}`；老存档读入时全部为 0，**不需要升 schema**。
- 抽走后留下的空隙同样记在货物上（放顶 / 拾起时压实，理货归位），不自动下沉（§2.4）。

## 3. 翻看

- 面对货堆时，每份货只露出一条**边缘条**。要确认图案和颜色，必须点击边缘进行**【翻看】**，掀起一角看到一小块区域。
- 翻看得到的是**部分信息**：
  - 纯色围巾：几乎不会认错。
  - 图案围巾：边缘区域可能只含图案的一部分；与库中其他 SKU 相似时存在**认错概率** `p_confuse(sku, visible_region)`，由 SKU 之间的视觉相似度表驱动。
  - 认错是认知层事件：玩家看到的是一个"推断出的 SKU"，真相层不变。
- 翻看消耗时间（营业中会被客人耐心惩罚）。
- **强化记忆**的作用在这里落地：对最近操作过的槽位，悬浮框直接以**文本**显示名称 / 颜色 / 数量（见 02 文档 §2.2），无需翻看、不会认错。
- 翻看后信息进入 `Knowledge`，带 `precision` 与 `may_be_wrong` 标记；数学能手不影响这里（它只修正数值类提示）。

## 4. 放回与顺序

- **抽出的货物不能插回原位**，只能放到某个堆的**顶部**。
- 每次放顶会改变堆的顺序，`disorder` 上升：同款被分散、颜色不连续、常卖款被压到底下。
- `disorder` 影响：
  - 下次找货需要翻看的次数（信息成本）
  - 平均 N（体力成本与倒塌风险）
  - 展示度（乱堆看着不吸引人，轻微负修正）
- **理货**：对一个槽位发起整理，把整堆取下按玩家指定顺序重新叠放。耗时与堆高成正比，营业中做会损失客流。员工可代劳（质量由其整理技能决定）。

## 5. 玩家不亲自拿货时

| 执行者 | 出错概率的决定因素 |
|---|---|
| **客人自取**（玩家忙于别处、或客人等不及自己上手） | 基础概率较高；性格【马虎】↑、耐心低↑、**头一次来**（不熟悉店里摆放）↑；常客↓ |
| **员工** | 由员工的整理 / 搬运技能等级决定；心情差、摸鱼时↑ |
| 玩家 | 由抽取小游戏的实际表现决定 |

- "出错" = 按 §2.2 同样的 `p_collapse` 与位移规则结算，只是 `d` 不由玩家操作产生，而是从执行者属性采样。
- 出错结果在**整体店铺界面**上可见：对应货架 / 货柜前出现一地货物的贴图，玩家一眼能看到哪里塌了，但看不到塌的是什么（除非走过去看 / 有记忆信息）。
- 倒地货物在拾起前**不可售**，且会阻碍该通道的通行（拿取路径变长）。
- **品质**：品质开关关闭时，倒地**不影响品质**，拾起即恢复。开启品质附属开关**【平整】**（04 文档 §2.2、05 文档 §1.2）后，倒地货物的 `flatness` 百分比下降，须执行**【拉平】**`smooth_item` 恢复（恢复率与上限按材质），否则上架 / 售出时折价。

## 6. 数据与接口补充

```
ActionAPI 新增
  pull_item(stack, index, pull_input | actor_profile) -> PullResult
  peek_item(stack, index, actor) -> PerceivedSKU        # 翻看，写入 Knowledge
  place_on_top(item, stack, actor)
  restack(stack, desired_order, actor)                   # 理货
  pick_up_pile(stack, actor)                             # 拾起倒地货

PullResult
  success, collapsed, displaced, time_cost, d (偏差分)

Knowledge 新增
  perceived: {item_id: {sku_guess, confidence, may_be_wrong}}
```

- `pull_item` 的 `pull_input` 来自玩家小游戏，`actor_profile` 来自客人 / 员工；两者都归一化成偏差分 `d` 后走同一结算函数。这样 NPC 出错与玩家出错是同一段代码。

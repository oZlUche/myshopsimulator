## 1. 风格与尺度

| 项 | 定 | 说明 |
|---|---|---|
| 风格 | 像素风，开罗式仰视斜 45° | 简洁的大头小身人物，物件要有顶面 + 正面，细节靠 1–2 像素的高光 / 阴影而不是靠线条 |
| 美术像素 | 标清档 **1 美术像素 = 2 屏幕像素**（`Iso.PX`）；高清档 1 美术像素 = 1 屏幕像素，图是标清的两倍 | 坐标一律按标清单位算，1280×720 的窗口里等于 640×360 的像素画。任何缩放只能是 0.5 的整数倍（`AreaView._fit` 已这么取）。分辨率策略见 §6 |
| 地面一格 | 32×16 美术像素（屏幕 64×32） | 标准 2:1 菱形，每行每边宽 2 像素，相邻格无缝 |
| 人物 | 一帧 24×32 美术像素，脚底在第 30 行 | 头 12×12，身 10×8，腿 5，鞋 2；约一格半高 |
| 光照 | 来自屏幕左上 | 顶面最亮，朝左前的面原色，朝右前的面暗 28%；人物右侧 2 列为背光 |
| 轮廓 | 深色半透明（#14121a，α 0.6），只描外轮廓 | 内部不描线，用色块对比区分 |
| 文字 | 暂用系统字体 | 中文像素字体待定（候选：缤纷像素 Fusion Pixel，OFL 可商用） |

## 2. 出图流程

- 所有精灵由 `tools/pixelart/gen_sprites.py` 生成到 `assets/sprites/`（标清）和 `assets/sprites_hd/`（高清，由 `gen_hd.py` 以标清为底放大两倍再补细节），**脚本和 PNG 都提交**。
  高清图必须正好是标清的两倍大（脚本里有断言），文件名一一对应，游戏只按档位换目录。
  改尺寸时同步改 `scenes/view/iso.gd` 里的常量（`FW` `FH` `FOOT_Y` `FRAMES` `HAIR_STYLES`）。
- 想手绘细修时直接改 PNG（Aseprite 等）也可以，但之后别再跑脚本覆盖；或者把改动写回脚本。
- `python3 tools/pixelart/gen_sprites.py preview 路径.png` 会拼一张示意图，不进游戏。
- 游戏内真实效果：`SHOTS=目录 xvfb-run godot --path . --rendering-driver opengl3 --script res://tests/tools/ui_smoke.gd` 截一旬各界面的图；
  `tests/tools/art_showcase.gd` 是美术陈列室，把每种地面、人物朝向 / 帧 / 发型、设备（带货）各画一遍，同样支持 `SHOTS`，CI 里无界面跑一次保证绘制函数不报错。

## 3. 人物精灵规范

- **分层上色**：人物按层出图，可换色的层是灰度 + 透明（255 受光、190 背光、140 深阴影），游戏里按颜色 `modulate` 乘上去；固定色的层直接 RGBA。
  这样玩家、员工、客人、路人共用同一套帧，只换颜色和发型。
- 层与绘制顺序：阴影 → 轮廓（随发型）→ 皮肤 → 上衣 → 裤子 → 鞋 → 头发 → 脸 → 围巾（可选）。
- **方向**：4 向。0 右前、1 左前（脸朝镜头）、2 右后、3 左后（背对）。1/3 是 0/2 的镜像。`Iso.facing_of()` 从格坐标方向换算。
- **帧**：4 帧走路循环（站 → 迈左 → 站 → 迈右），6.4 帧/秒；站立用第 0 帧。迈步时身体上抬 1 像素，手臂前后摆。
- **姿态**：`walk` 走路（上面那套）；`push` 推手推车（07 §2.1）——正面两条手臂都伸向身前握车把（远臂的前臂横过胸前，近臂从肩膀下来再往前），背面上臂往前收、手被身体挡住；腿照常走。
  推车姿态是另一套层 `person_push_*`，头发共用 `hair.png`。车不在人物图里：`Iso.pushed_cart(foot_g, facing, back)` 给出车该画在哪一格、用哪个朝向、画在人前还是人后——往 +gx / +gy 推时车在镜头这边（先画人再画车，车把压在手上），往 -gx / -gy 推时车在人身后。车把那头紧挨着手，车身在人前方 0.9 格起。
- **发型** 7 种（`Iso.Hair`）：短发、偏分、波波头、长发、马尾、发髻、鸭舌帽。
- **打扮**：`Iso.outfit_full(seed)` 按 id 稳定地给出上衣、裤子、发色、发型，四分之一的人围一条围巾（颜色取自 SKU 色表）。
- 接口：`Iso.draw_person(ci, foot, body, hair, facing, phase, back, k, style, pants, scarf, pose)`，前 8 个参数与旧版相同，老调用不用改，`pose` 省略即走路；`Iso.person_rect(foot)` 给点击判定。

## 5. 店面 / 仓库设备

尺寸按代码线程的 [07-店面仓库与整箱整包](07-店面仓库与整箱整包.md)：全部 1×1 格（手推车 0.9×0.7），高度是**美术像素**（屏幕像素 ÷ 2）。
每件设备都是"顶面 + 朝左前（SW）的面 + 朝右前（SE）的面"的方块，开口（层板、柜门、玻璃）朝哪边就有哪一张图，`_sw` / `_se` 各画一张而不是镜像，光照才一致。
`tools/pixelart/gen_equipment.py` 里的 `IsoBox` 负责方块几何，细节画在"面坐标"（u 沿面横向、v 从地面往上）里；元数据写进 `assets/sprites/equipment.json`（`size` 尺寸、`anchor` 地面菱形最上角在图里的位置、`H` 高度、`tiers` 每层层板高度、`slot` 放货的格内偏移）。

|---|---|---|
| `shop_shelf` 货架 | 39 | 三层开放层板，层高 12；每层放一叠围巾（`extra.tiers`） |

接口：`Iso.draw_equipment(ci, origin, g, kind, facing, extra)`，`g` 是设备占的那格；`Iso.equipment_height(kind)` 给屏幕像素高度（和 `draw_box` 的 h 同单位）；
需要自己摆小物件时用 `Iso.draw_sprite(ci, origin, g, name, color, up)`，`up` 是往上抬几个美术像素。

## 6. 分辨率策略与高清档

游戏基准分辨率 1280×720，`canvas_items` 拉伸。标清档 1 美术像素 = 2 屏幕像素，所以整体放大 1.5×（1080p）、2×（1440p）、3×（4K）时，一个美术像素分别是 3、4、6 个物理像素，都是整数，像素不会忽粗忽细。1366×768、1600×900 这类非整数倍会有轻微不均匀，属于已知取舍。

**高清档**（`assets/sprites_hd/`）：同一套设计放大两倍再补细节 —— 圆头、眼睛高光与眉毛、V 领、袖口、腰带、裤线、鞋底、发丝与高光、围巾流苏；地砖缝与每块砖的色差、路面骨料、草叶、卵石；设备的层板高光、门板倒角、把手高光、立柱孔、木纹、标签字迹、袋子褶皱。1 美术像素 = 1 屏幕像素（基准分辨率下），所以在 1440p / 4K 上一个美术像素仍有 2 / 3 个物理像素，高清图的细节才真正显示出来；在 720p / 1080p 上用高清档等于 1 / 1.5 个物理像素，1080p 会不均匀，不推荐。

**切换**：`Iso.set_tier("sd" | "hd" | "auto")`，游戏启动时 `Game._ready` 按 `ART_TIER` 环境变量或 `auto`（窗口高度 ≥ 1300 用高清）设置；设置界面的开关待加。所有绘制函数按 `Iso.S` 换算取图区域，调用方的坐标、`equipment.json` 元数据都按标清单位，不用改。
特写面板（讲价时的客人、抽取小游戏的正面视图）将来可以在任何分辨率下直接用高清图放大显示，这是高清档的第二个用途。

截图对比：`ART_TIER=hd SHOTS=目录 xvfb-run godot --path . --rendering-driver opengl3 --script res://tests/tools/art_showcase.gd`。

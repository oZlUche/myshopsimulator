## 1. 技能系统总则

- 技能效果全部落在**认知层**（见总览 §2.2）：要么提高对真相层的采样精度 / 范围 / 频率，要么减少一个手动步骤。没有技能直接改变真相层的数值。
- 每个技能的每一级在数据表里是一条记录：`{skill_id, level, effect_type, params}`，由 `Sampler` 统一读取。新加一级只加一行数据，不加代码分支。
- **【数学能手】是跨技能修正器**：它的 Lv3 / Lv6 不产生自己的信息，而是把其他技能已经给出的定性信息变成定量信息。实现上，每条认知提示都带一个 `precision` 字段（0 = 只有定性描述，1 = 模糊区间，2 = 精确数值），其他技能决定"有没有这条提示"，数学能手决定 `precision` 的上限。
- **经验是一个共用池**：所有经营行为（经营时长、成交量、整理、议价、开车、看账……）产出同一种经验值，进入 `Player.xp`。玩家自行把经验**分配**到任意技能的下一级节点上；节点累计达到阈值即点亮。分配可以是部分的（往一段里倒一部分经验），也可以先存着不投。
- 每一级有独立阈值 `xp_cost`，随等级递增；不同技能的同一级阈值可以不同（例如审美积累 Lv7 很贵）。

## 2. 玩家技能表

### 2.1 审美积累（趋势预报）

对应真相层：`TrendState`（颜色 / 图案）。

| 级 | 效果 | 采样参数 |
|---|---|---|
| 1 | 随机性地得知接下来某**一种**图案或颜色会成为潮流 | 触发：随机；维度：1；数量：1；时长信息：无 |
| 2 | 得知更多颜色 / 图案 | 数量：2 |
| 3 | 得知更多颜色 / 图案 | 数量：3 |
| 4 | 得知潮流的**大致时长**（"一阵子" / "一个季度" / "很长时间"） | 时长 precision：1 |
| 5 | 得知更具体的时长（"约 6 旬"） | 时长 precision：2 |
| 6 | 改为**周期性**得知（每旬末结算时固定给出预报，不再随机） | 触发：每旬 |
| 7 | 得知**所有**即将流行的具体图案和颜色 | 数量：全部 |

- 预报内容默认是定性的（"紫色会比较流行"）；叠加数学能手 Lv3 变成"需求量提升 20%~40%"，Lv6 变成更窄的区间。
- 预报对象是 `TrendState.scheduled_jumps` 与未来漂移方向，不是宏观经济（后者留给未来可能的"经济嗅觉"技能）。

### 2.2 强化记忆（整理辅助）

对应真相层：`Slot.content`。

| 级 | 效果 |
|---|---|
| 1 | 最近 **1** 次操作过的货物区域，鼠标悬停时显示悬浮框：货物**名称** |
| 2 | 悬浮框显示名称 + **颜色** |
| 3 | 范围扩大到最近 **3** 次操作的区域 |
| 4 | 悬浮框显示**每种货物 + 颜色的数量** |
| 5 | 最近 **10** 次 |
| 6 | 最近 **20** 次 |

- **模型修正**：记忆按"操作次数"而不是"时间"衰减。实现为一个容量为 N 的环形队列 `recent_slots`，每次 `move_box` / `place_item` / `take_item` 把目标槽位推到队首并去重；N 由技能等级决定。总览 §2.2 原先写的"有时限"改为"有次数限制"。
- "货物区域"= 一个 `Slot`（仓库格、展架格、店内仓库格、后备箱格、摊位格）。
- 有悬浮框的槽位**无需翻看、不会认错**（翻看机制见 03 文档 §3）。
- 悬浮框显示的是**操作当时**的内容快照，不是实时真相。如果之后员工动过那个格子，玩家看到的就是过期信息，这与"标签可能过期"的设计一致。

### 2.3 客人观察

对应真相层：`CustomerProfile`。

| 级 | 可见信息 | 对应字段 |
|---|---|---|
| 1 | 喜好（想要什么颜色 / 图案 / 材质） | `preference_vector` |
| 2 | 耐心 | `patience` |
| 3 | 预算 | `reserve_price` |
| 4 | 性格（议价策略、犹豫度、善意） | `haggle_strategy`, `hesitation`, `kindness` |
| 5 | **回购几率** | `loyalty_base` |

- Lv5 的设计意图：对先天回购率低的客人可以宰一笔；对其他客人，开高价即使成交也会损失回头客。
- **架构影响**：这要求客人是**持久的个体**而不是一次性生成的。需要 `CustomerRegistry`：固定一批有 ID 的常客 + 流动的过路客；每次成交按 `(实付价 − 心理价) / 心理价` 调整该客人的 `return_probability`；下次客流生成时按 `return_probability` 决定常客是否回来。总览 §4.3 需补充。

### 2.4 员工观察

对应真相层：`Employee` 的隐藏字段。

| 级 | 可见信息 | 对应字段 |
|---|---|---|
| 1 | 部分性格（随机揭示 1–2 个特质） | `hidden_flaws` 子集 |
| 2 | 当前心情 | `mood` |
| 3 | 满意度 | `satisfaction` |
| 4 | **真实技能等级**（对比自称） | `skill_levels` vs `claimed_skill_levels` |
| 5 | 全部性格 | `hidden_flaws` 全集、`diligence`、`honesty` |
| 6 | 员工随机冒出的**意图**（工作 / 摸鱼 / 抱怨 / 偷窃） | `EmployeeAgent.current_intent` |

- Lv6 是实时的：员工头顶偶发气泡显示他此刻打算做什么。这是"看穿偷窃"最直接的通道，但只在念头冒出的瞬间可见，不保证全部捕捉。

### 2.5 数学能手（跨技能修正器）

| 级 | 效果 | 类型 |
|---|---|---|
| 1 | 可以快速将已算出的各项价格**求和** | 减少手动步骤（手动结账时） |
| 2 | 查看账目时可以**确认数字是否有出入**（有 / 无，不指明哪里） | 对账 precision 0 |
| 3 | 使其他技能得到**准确的数据**：定性 → 区间（"紫色会流行" → "紫色需求提升 20%~40%"） | 全局 precision 上限 → 1 |
| 4 | 可以快速算出**每样商品的总价**（单价 × 数量）；配合 Lv1 即可快速算账 | 减少手动步骤 |
| 5 | 查看账目时可以算出**具体的出入**（哪一笔、差多少） | 对账 precision 2 |
| 6 | 使其他技能得到**更精确的数字**：区间收窄 | 全局 precision 上限 → 2 |

- 总览 v0.3 里的【数字敏感】**并入本技能**的 Lv2 / Lv5，不再单列。
- Lv2 / Lv5 只在开启"员工贪腐"时有实际意义；未开启时账目永远没有出入。
- Lv1 / Lv4 只在开启"手动结账"时有实际意义。

### 2.6 口才（议价）

对应：`HaggleState`。

| 级 | 效果 |
|---|---|
| 1 | 提高议价成功率 |
| 2 | 议价失败时减少客人增长的不满 |
| 3 | 进一步提高成功率 |
| 4 | 使本来不满意某个款式的客人**放宽条件**（偏好匹配阈值降低） |
| 5 | 减缓客人耐心降低的速度 |
| 6 | 提升客人**回购率** |

- Lv6 同样依赖 `CustomerRegistry`（见 §2.3）。

对应：开车小游戏模块。

| 级 | 效果 |

### 2.8 吆喝（仅摆摊阶段）

对应：摆摊场景的 `StallArea` 与过路客逗留判定（总览 §6.9）。

| 级 | 效果 | 参数 |
|---|---|---|
| 1 | 增加玩家的周遭范围（N×M 区域扩大） | `area_radius +1` |
| 2 | 增加客人的逗留几率 | `stay_p ×` |
| 3 | 增加客人的购买倾向 | `intent +` |
| 4 | 增加客人的议价上限 | `reserve_price ×` |
| 5 | 进一步增加周遭范围 | `area_radius +1` |

- **只在摆摊阶段可学习、可生效**。开店后该技能不再出现在技能面板。
- **开店后的转化**：开店时，吆喝等级一次性转化为店铺的**初始客流量加成** `base_traffic_bonus`，等级越高加成越高（如 Lv1 +4%、Lv5 +20%，数值待调）。这是一个**独立的加成项**，在客流计算里单列（`traffic = base × (1 + stall_legacy_bonus) × 其他增益`），不与展示度、口才、季节等增益合并，玩家在结算面板能看到它单独的一行。转化后吆喝行从技能面板移除。

### 2.10 搬运（2026-10-22 新增）

对应：「手上」暂存槽（[03](03-货堆与抽取.md) §4）、框选批量拿取（03 §2.6）、抱箱与推车（[07](07-店面仓库与整箱整包.md) §2）。`skill_id = carrying`。

这是和【驾驶】、【吆喝】同类的**"买回时间"技能**：它改的是玩家自己的动作上限（能拿多少、拿多快、搬着走多快），不改任何货物或世界的真相层数值，所以不违反 §1 的原则。

| 级 | 效果 | 参数 |
|---|---|---|
| 1 | 手上散货上限 3 → **4** | `hand_items 4` |
| 2 | 拆顶、放顶、抱起 / 放下箱包的耗时 **×0.8** | `handle_time_mult 0.8` |
| 3 | 散货上限 → **5**；开店后包上限 3 → **4** | `hand_items 5`，`hand_packs 4` |
| 4 | 抱箱走路 ×0.6 → **×0.75**；推车走路 ×0.8 → **×0.9** | `box_walk_mult 0.75`，`cart_walk_mult 0.9` |
| 5 | 散货上限 → **6**；包上限 → **5** | `hand_items 6`，`hand_packs 5` |
| 6 | 可同时抱 **2 箱**（走路 ×0.5） | `hand_boxes 2` |

- 三选一的规则不变（散货 / 箱 / 包不能混拿），每种形态按各自上限判断。
- 和框选的关系：框选一次能拿的份数 = 手上余量，所以这项技能直接决定"一把抓几条"。
- 阶段门：摆摊阶段上限 **3**（Lv3 里"包"的部分开店后才有意义）；Lv4–6 开店后解锁，无其他前置。
- 经验阈值初值 `[60, 120, 200, 320, 480, 700]`，待实测。
- **当前实现值（PR #29）**：按上表；`Inventory.hand()` 每次按技能重设上限（`Inventory.player` 由 `GameState` 连上，不存档）；Lv2 的 ×0.8 覆盖拆顶、放顶、抱起 / 放下箱包、从箱里拿包 / 放回、从开口包拿一条；抱箱减速（1 箱 ×0.6、Lv4 ×0.75、2 箱 ×0.5）也在这次一并实现（之前 07 有写、代码没有）。
- 员工的"搬运"技能（§3）以后用同一张表的 `hand_*` 字段决定一趟搬几件。

## 3. 员工技能与自称

- 员工拥有与工作相关的技能（搬运、整理、销售 / 口才、驾驶、记账）。
- 真相层：`skill_levels`。认知层：`claimed_skill_levels`，招聘时和日常对话中员工**自称**的等级。
- 自称偏差由性格决定：
  - 爱摸鱼（`lazy`）：倾向于**报低**（少干活）
  - 爱表现 / 贪（`greedy`、`boastful`）：倾向于**报高**
  - 诚实（`honesty` 高）：接近真实
- 玩家得知真实水平的途径：
  1. 员工观察 Lv4 直接显示
  2. **谈心**有概率揭示（概率随 `honesty` 和当前满意度上升）
  3. 观察工作结果（干得慢、摆错位置）—— 行为线索的一部分

## 4. 谈心（修订）

总览 v0.3 把"谈话"定义为纯信息收集、不影响心情。本次修订为：

- 谈心**既是信息收集，也是关系维护**：
  - 有概率得知员工真实技能、部分性格（概率受 `honesty`、满意度影响）
  - **提升满意度**（通过 §5 的"互动"项），进而**降低摸鱼概率**
  - 例外：性格驱动的摸鱼（`lazy` 特质）不受谈心影响，只能靠监督、罚款或换人
- 谈心有冷却 / 边际递减：同一旬内多次谈心效果递减，避免刷满意度。
- 批评、罚款、开除、报警的规则不变（总览 §4.4）。

## 5. 员工满意度模型

满意度是一个**有界的复合加法**：

```
bounds       = wage_band(wage / wage_expectation)        # 薪资满意度决定 [lo, hi]
raw          = interaction                                # 谈心、批评、罚款等互动的累计（有衰减）
             + workload_term(近期工作量 vs 体能)          # 过劳为负，适度为正
             + mood_now                                   # 当前心情
             + mood_accum                                 # 累积心情：长窗口 EMA（"一直很累" / "一直很开心"）
             + mood_trend                                 # 心情变化趋势：短窗口斜率（"心情越来越差"）
satisfaction = clamp(lo + (hi − lo) · sigmoid(raw), lo, hi)
```

- **薪资只决定上下限**：工资再高，被天天骂也到不了 `hi`；工资再低，再怎么谈心也突破不了 `lo`。
- `mood_accum` 用长窗口（如 λ=0.95 的 EMA），`mood_trend` 用短窗口斜率（如最近 3 旬的线性回归斜率）。两者分开，才能表达"虽然现在还行，但越来越差"。
- 满意度驱动：摸鱼概率、自称技能的偏差、贪腐概率（如开启）、离职概率。
- 认知层：员工观察 Lv2 看 `mood_now`，Lv3 看 `satisfaction`；两者都看不到的时候，玩家只能从行为线索（抱怨台词、动作变慢）推断。

## 7. 技能分阶段解锁

原则：**摆摊阶段只开放与摆摊相关的技能，且有等级上限；开店后全部开放。** 用"阶段门 + 少量前置"的混合方案，而不是完整技能树：阶段门实现成本几乎为零，前置只在确有依赖关系的地方加。

### 7.1 阶段门（摆摊阶段等级上限）

| 技能 | 摆摊阶段上限 | 理由 |
|---|---|---|
| 吆喝 | 5（全开） | 摆摊专属 |
| 搬运 | 3 | 摊上拿几条够用；抱箱、推车、抱两箱是开店后的事 |
| 口才 | 3 | 议价是摆摊核心；Lv4 放宽款式、Lv6 回购留给开店 |
| 客人观察 | 2 | 喜好、耐心够用；预算、性格、回购留给开店 |
| 审美积累 | 2 | 能感知趋势存在即可 |
| 强化记忆 | 2 | 行囊与摊位格子少，Lv3+ 用不上 |
| 数学能手 | 1 | 只有快速求和有用；对账需要账本与员工 |
| 员工观察 | 0（锁定） | 没有员工 |
| 驾驶 | 0（锁定） | 没有车 |

- 实现：`SkillDef.phase_cap: {stall: int, shop: int}`，升级按钮在 `level >= cap[current_phase]` 时禁用并提示"开店后解锁"。
- 经验仍然可以在上限处继续累积（溢出保存），开店后一次性可用，避免浪费玩家前期的练习。

### 7.2 前置（少量、只在有真实依赖处）

| 目标 | 前置 | 理由 |
|---|---|---|
| 数学能手 Lv2 / Lv5（对账） | 已开店 | 没有账本就没有对账 |
| 数学能手 Lv3 / Lv6（精度修正） | 审美积累 ≥1 **或** 客人观察 ≥1 | 没有定性提示就没有可修正的对象 |
| 口才 Lv4（放宽款式） | 客人观察 ≥1 | 要先看得出客人想要什么 |
| 口才 Lv6（提升回购） | 客人观察 ≥5 | 回购率先可见再可影响 |
| 员工观察 全部 | 已开店且雇有员工 | 没有观察对象 |
| 驾驶 全部 | 已拥有车辆 | 没有车 |

- 实现：`SkillLevelDef.requires: [{skill_id, level} | {flag}]`，与阶段门同一处校验。
- 以上是草案，数值在阶段 0 / 阶段 1 实测后调。

### 7.3 技能面板形态：一技能一行，一级一段

**决定：不做多棵技能树，用『一技能一行、每一级一段』的分段进度条布局。**

理由：
- 10 个技能（含抽货、搬运）共约 55 个节点，每个技能内部本来就是严格线性的（Lv2 必须在 Lv1 之后），画成树会得到 10 条几乎不分叉的链，树的形式没有带来真实的选择。
- 真正的策略选择来自**共用经验池往哪里投**，而不是拓扑结构。分行布局让『我有 300 经验，是补口才 Lv4 还是开客人观察 Lv3』一眼可比。
- 树需要为跨技能连线编造理由，容易显得牵强；§7.2 里那几条真有依赖的前置，用行与行之间的**虚线连接**画出来就够了，既有树感又不用维护整棵图。
- 实现与 UI 成本最低，且数据模型（`SkillLevelDef.requires`）与树完全相同，将来若真想改成树，只换展示层。

布局草案：
```
吆喝      [■■■■■]                    ← 摆摊专属，开店后整行灰掉
口才      [■■■|□□□]                  ← | 为阶段门，右侧"开店后解锁"
客人观察  [■■|□□□]      ┐
                          ├ 虚线：口才 Lv6 需客人观察 Lv5
数学能手  [■|□□□□□]      ┘ 虚线：Lv3 需审美/客人观察 ≥1
审美积累  [■■|□□□□□]
强化记忆  [■■|□□□□]
员工观察  [🔒□□□□□□]                  ← 开店并雇人后解锁
驾驶      [🔒□□□□□□]                  ← 拥有车辆后解锁
```
- 每段显示 `已投入 / 阈值`，点亮的段显示效果摘要，悬停显示下一段效果。
- 未点亮但可投的段高亮；被阶段门或前置锁住的段灰显并写明解锁条件。

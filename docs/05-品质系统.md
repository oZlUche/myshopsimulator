## 0. 定位

**【品质】是进阶难度的代表属性。** 基础游戏里围巾没有品质概念，每一条都是优质品；开启品质总开关后，围巾才获得品质维度，各附属开关只是增减"品质会被什么影响"。

- 总开关 `quality`，附属开关 `quality.mold` / `quality.flatness` / `quality.misweave` / `quality.misdye`。
- **总开关打开 ⇒ 所有附属开关一并打开**；玩家可再逐个关掉附属开关，但**至少保留一个**，否则总开关自动关闭。
- 附属开关全关 ⇒ 总开关不能打开。
- 其他进阶难度（手动结账、员工贪腐、批发拖欠付款）与品质无关，保持独立开关。

## 1. 四个品质维度

| 维度 | 类型 | 可见性 | 修复 | 归责 |
|---|---|---|---|---|
| 霉菌 `mold` | 真 / 假 | 直接可见 | **不可修复**，直接报废 | 需追溯：厂商 → 退货；运输 → 索赔 |
| 平整 `flatness` | 百分比 0–100% | 直接可见（褶皱贴图随百分比变化） | **【拉平】**，恢复程度按材质 | 自身操作（倒地、挤压）为主 |
| 错织 `misweave` | 真 / 假 | **隐藏**，需【观察】才能发现 | 不可修复 | 厂商 → 退货 |
| 错染 `misdye` | 真 / 假 + 区域大小 `area` ∈ (0,1] | 隐藏，需【观察】；区域越大越易在观察时发现 | 不可修复 | 厂商 → 退货 |

### 1.1 霉菌
- 一旦 `mold = true`，该围巾**无法出售**，只能报废。
- 来源（真相层记录在 `provenance.mold_cause`）：
  - **厂商**：到货时已带霉（厂商仓储差）
  - **运输**：途中淋湿 / 受潮（物流公司参数、路况、玩家开车表现）
  - **自家仓库**：湿度累积（§4 连续风险）
- 发现霉菌后玩家可发起**【追溯】**：选择归责对象（厂商 / 物流 / 自己）。
  - 归责正确 → 进入退货或索赔流程（§3）。
  - 归责错误 → 对方拒绝，耗费时间，并降低与该厂商 / 物流公司的关系值。
  - 玩家判断依据：收货时是否做过**【验货】**（箱子外部是否潮湿、箱内是否有味）、仓库湿度记录、货物在自家存放的旬数。这些都是认知层信息；真相层始终知道真实原因。

### 1.2 平整
- `flatness` 从 100% 向下掉。来源：倒地（03 文档 §5）、运输颠簸、长期压在堆底（按堆位与旬数累积）。
- **【拉平】** `smooth_item`：恢复量 `Δ = recover_rate[material] × 操作质量`，且有**恢复上限** `cap[material]`：

| 材质 | 恢复率 | 上限 | 现实参考 |
|---|---|---|---|
| 羊绒 / 羊毛 | 高 | ~98% | 蒸汽一熨即平 |
| 真丝 | 中 | ~95% | 怕高温，难彻底 |
| 棉麻 | 中 | ~90% | 顽固折痕 |
| 腈纶 / 混纺 | 低 | ~85% | 化纤定型折痕难消 |

- 平整低于阈值时影响售价（线性折价）与客人满意度；设备"平整台 / 熨烫机"提升操作质量与速度。

### 1.3 错织
- 到货时由厂商参数决定 `misweave = true/false`，**不显示**。
- 玩家对单件执行**【观察】** `inspect_item`（耗时）才有概率发现：`p_detect = base × 观察等级修正`。
- 未发现而售出 → 售后有概率被**退还**（`p_return_misweave`，常数，待调），退还会扣信誉并退款。
- 发现后 → 可向厂商**退货**（§3）。

### 1.4 错染
- 同错织，但多一个 `area ∈ (0,1]`（错染区域占比）。
- 观察时发现概率随 `area` 上升。
- **未发现而售出后的退货率**：

```
p_return(area) = area ^ (1 − area ^ (1/e))
```

| area | 0.01 | 0.05 | 0.1 | 0.2 | 0.3 | 0.5 | 0.7 | 0.9 |
|---|---|---|---|---|---|---|---|---|
| p_return | 0.023 | 0.135 | 0.268 | 0.487 | 0.650 | 0.856 | 0.957 | 0.996 |

曲线前段很陡：10% 的错染区域已有约 27% 退货率，一半区域接近 86%。这意味着小瑕疵不能赌，必须靠观察把它筛出来。

## 2. 数据模型

```
ScarfItem（扩展）
  quality: QualityState | null        # null = 品质开关关闭或该件视为优质
  provenance: Provenance

QualityState
  mold: bool
  mold_cause: enum [supplier, transit, own_warehouse] | null   # 真相层
  flatness: float (0–1)
  misweave: bool
  misdye: bool
  misdye_area: float (0–1)
  inspected: bool                     # 认知层：玩家是否观察过
  known_defects: [enum]               # 认知层：已发现的缺陷

Provenance
  supplier_id, batch_id, purchase_period
  logistics_id, route_id, transit_events: [wet, bump, ...]
  warehouse_history: [{location_id, from_period, to_period}]
  handling_count: int                 # 离散风险计数（§4）

Supplier（新实体，真相层参数隐藏）
  id, catalog, price_level
  defect_rate_misweave, defect_rate_misdye, misdye_area_dist, mold_rate_at_source
  return_policy: {accept_p, days_to_refund}
  relationship: float                 # 玩家与该厂商的关系

LogisticsCompany（新实体，真相层参数隐藏）
  id, price_level, speed
  wet_rate, bump_rate
  claim_policy: {accept_p, days_to_pay}
  relationship: float
```

- 品质开关关闭时，`quality` 字段为 `null`，所有品质逻辑短路。这也是存档前向兼容的自然形态（见 01 §7.1）。

## 3. 退货与索赔流程

```
发现缺陷 → 【追溯】选择归责对象 → 发起 退货(厂商) / 索赔(物流)
  → 对方按 accept_p 与关系值决定受理
  → 受理：进入账期（days_to_refund / days_to_pay），到期入账
  → 拒绝：时间损失、关系值下降
```

- **与【批发拖欠付款】联动**：该开关开启时，厂商退款与物流赔付也会按同一套"拖欠"逻辑**延期**（受宏观经济 `wholesale_credit_risk` 影响），玩家需要催款。关闭时按 policy 的固定天数到账。
- 退货需要把实物寄回（占用一次物流），索赔只需单据。
- 多次正确追溯会提升玩家对该厂商 / 物流公司隐藏参数的认知（认知层逐步逼近真相）。

## 4. 中途开启（调试台）的规则

品质总开关在新档开始时选择；通过调试台**中途开启**时：

1. **存量货物**：所有已持有围巾的 `quality` 初始化为**优质**（`mold=false, flatness=1, misweave=false, misdye=false`）。
2. **风险从零开始累积**，分两类：
   - **连续风险**（随时间）：仓库湿度暴露积分 `H = Σ humidity(t) · dt`，`p_mold = 1 − exp(−k_m · H)`；堆底压迫积分同理作用于 `flatness`。
   - **离散风险**（随次数）：每次搬运 / 抽取 / 倒地使 `handling_count += 1`，`flatness` 按次掷衰减；倒地触发 03 文档 §5 的皱规则。
3. **后续进货**：到货品质由厂商与物流公司的**隐藏参数**决定（§2）。开启品质后，供应商目录与物流公司列表会**提供更多选择**（便宜但差、贵但稳），选择本身成为新的信息博弈。
4. 开启时刻记录 `quality_enabled_period`，用于结算界面区分"开启前后"的统计。

## 5. 认知层入口（买回来的方式）

| 维度 | 技能 / 设备 / 员工 |
|---|---|
| 霉菌 | 收货【验货】、除湿机（设备）、仓库选址、物流公司选择、追溯经验 |
| 平整 | 抽取技能（少塌）、平整台 / 熨烫机、员工代为拉平 |
| 错织 / 错染 | 【观察】动作、观察类技能（待定：并入客人观察？新增【验货眼力】？）、员工验货（按其技能） |
| 归责 | 验货记录、对厂商 / 物流的关系与历史 |

- 待定：是否新增一项玩家技能【验货】专门提升观察发现率与追溯准确率，或把它挂到现有技能上。
